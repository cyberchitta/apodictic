1.16. The vocabulary🔗

Reference. These are the definitions the statements above are written in. Nothing earlier depends on having read them.

Terms such as library, claim, condition and frame are explained under The Result. What the audit turned up, its findings, is under The finding and The other findings.

The basic vocabulary is deliberately bare. Preference is just a relation. It is not assumed transitive. It is not assumed to rank every pair. Time is not assumed ordered. Properties get added when a theorem forces them. So far one has been added as a claim: asymmetry (AsymmetricPreference, under The claims). It says that if an agent prefers one bundle to another at a time, he does not also prefer the second to the first. Others enter as conditions of particular theorems. Six theorems in the library use asymmetry:

  • The theorem relating the two routes uses it (Contrast.rothbard_entails_servedInOrder), under Mises's route.

  • The rival-plan theorem uses it (no_rival_swap_dominant), under The theorems.

  • Four theorems under Interest use it: the three loan theorems, and the check on the unrestricted rule (PureInterest.buysMore_of_unrestricted).

Apodictic.ActionFrame : Type 1

The vocabulary everything else is built from: bare types and bare relations. Nothing here has any property. Preference is not assumed transitive. It is not assumed to rank every pair. Time is not assumed ordered. A property gets added only when some theorem forces it. Every such forcing is a finding.

Constructor

Apodictic.ActionFrame.mk

Fields

Agent : Type

Acting persons.

End : Type

Ends: states of affairs an agent may value.

Means : Type

Means: scarce resources an agent may employ.

Time : Type

When action happens. It is explicit from the start. No order is assumed on it here.

Believes : self.Agent → self.Time → self.Means → self.End → Prop

Believes agent time means want: at that time, the agent believes that using those means helps bring about the end want. Nothing links a means to an end here except what the agent believes.

Prefers : self.Agent → self.Time → Set self.End → Set self.End → Prop

Prefers agent time X Y: at that time, the agent values the bundle of ends X above the bundle Y. This is the ranking behind the agent's choices. It is read as strict. But that reading is not built in: NO properties are imposed on this relation here, strict or otherwise. A theorem that needs one says so. Asymmetry, for one, enters as a claim the theorems that use it carry (AsymmetricPreference).

The ranking is kept apart from what the agent actually does. Three claims tie the two. Two run from an act to the ranking. DemonstratedPreference is stated of a trade. DemonstratedTimePreference is stated of an act across dates. One runs the other way, from the ranking to what he does with a stock. ActsInOrder is stated of an actual allocation. Each is asserted of the one trade, act or allocation a theorem is handed, never of every act. That follows a rule of method set out under The other findings.

The relation ranges over SETS of ends rather than single ends. The tradition draws no line between an end and a composite of ends. An end is "atomic", a single end, only relative to an action: it is one this action does not divide further. That is the same relativity as the size of a unit of supply, which is whatever enters the action as one thing (MES p. 28; see Stock). So there is ONE ranking, over bundles at whatever grain the problem has. An end in the ordinary sense is a bundle with one member (PrefersEnd). Independence of uses (IndependentUses, under The conditions) is bundle preference breaking down into preference between ends. A preference between two bundles that differ in exactly one end carries down to a preference between those two ends. A relation on single ends has no bundles to break down, so it could not state that condition at all. Ranging over bundles is what lets independence of uses be a named hypothesis, instead of something the vocabulary quietly enforces.

Audit note on shape: an assumption can hide in the shape of a structure, which fields it has and their types, where no signature shows it. Here a bundle is a Set, so it carries no multiplicity and no order. That is noted here, not judged.

Preference between two single ends. It is bundle preference between two one-member bundles. It is a definition, not a second relation.

The law of marginal utility is about a stock of units and what the agent would do with more or fewer of them.

The plan below, and an allocation further down, are each set against an action (Action). An action is one agent, at one time, using means he believes will bring about one chosen end. By acting he gives up at least one other end. Its definition is shown under Claims no theorem uses.

🔗structure
Apodictic.Stock (praxis : ActionFrame) (agent : praxis.Agent)
  (time : praxis.Time) : Type
Apodictic.Stock (praxis : ActionFrame)
  (agent : praxis.Agent)
  (time : praxis.Time) : Type

A stock of some good, held by one agent at one time. It is finitely many units the agent believes will do the same jobs.

"The same jobs" is the whole of what homogeneity means here. Each unit is believed to serve exactly the ends listed in the field serves: the ends this good can serve, by the agent's lights. That is a statement about BELIEF, not about preference. Nowhere is it said that the agent is indifferent between units. So preference can stay strict. And Rothbard's denial that indifference is ever demonstrated in action is not contradicted. Indifference between units is not assumed here, and no theorem needs it (see The other findings).

What counts as a unit is left open. units lists whatever enters the action as one thing. Rothbard holds that the law works "regardless of the size of the unit considered. The size of the unit will be the one that enters into concrete human action" (MES p. 28). His example is horses. Say the man "must consider only pairs of horses as the units to add or subtract from his stock". Then the pairs make a different stock. He "will construct a new and shorter scale of ends with fewer units of supply to consider" (p. 28). A good that "cannot be divided into homogeneous units for purposes of action" is a stock of exactly one unit.

🔗structure
Apodictic.AllocationPlan {praxis : ActionFrame} {agent : praxis.Agent}
  {time : praxis.Time} (stock : Stock praxis agent time) : Type
Apodictic.AllocationPlan
  {praxis : ActionFrame}
  {agent : praxis.Agent}
  {time : praxis.Time}
  (stock : Stock praxis agent time) : Type

The agent's plan for the stock. Take each subStock, each set of units he might have. The plan gives the ends he WOULD serve with exactly those units, at the stock's single time.

The plan is something new, over and above Action, and it has to be. Marginal utility is read off the plan: the ends it would serve with the larger of two sub-stocks and not with the smaller (marginalEnds). So the law needs the served ends told apart, by the sub-stock that would serve each. An Action has one chosen end. A single act of allocating cannot tell the served ends apart from one another. They all sit inside its one chosen end, as one package. Several acts at that time would still be what he does with the whole stock he holds. The law compares two sub-stocks, and the smaller is a part of the stock he might have held instead. What he would do with it is in the plan, and no act of the agent's exhibits it. So what the law of marginal utility rests on is not action at all. In the Lean, no derivation of the law uses Action.

The plan is indexed by WHICH units, not by how many. To say it depends only on the number of them is to say the units are interchangeable. That is not built in here. It is the named condition Homogeneous, assumed only where a theorem needs it.

Audit note on shape: an assumption can hide in a structure's fields, where no signature shows it. servesOnlyWhatItCan is the one condition left in the plan's fields. It is definitional. Take a plan that puts a unit to an end the good is not believed able to serve. That is not a coherent plan. It is not a situation that might obtain.

One unit to one end is NOT here, and is nowhere: no theorem needs it. Rothbard assumes it, and says he is assuming it. He writes "each unit of means is capable of serving one of the ends". He introduces it with "We assume for simplicity" (MES pp. 25–26). The ordering the law asserts turns out not to want it. Without it, an extra unit may add no new end: a horse can stand idle. The law speaks of every end a one-unit step adds (marginalEnds). Where the step adds none, the law is silent. That costs nothing: every plan that met the assumption is still a plan, and the law still holds of it (see The other findings).

Apodictic.AllocationPlan.mk

Fields

wouldServe : Finset praxis.Means → Finset praxis.End

The ends the agent would serve with exactly the units in subStock, and no others.

servesOnlyWhatItCan : ∀ (subStock : Finset praxis.Means), ∀ want ∈ self.wouldServe subStock, want ∈ stock.serves

A unit is only ever put to an end the good is believed able to serve.

Two conditions sit a level down, inside the structures the theorems take as arguments. They are fields of the stock, of the plan, and, on the history reading, of an allocation. That reading is under The ladder as a history.

  • servesOnlyWhatItCan is a field of the plan and of an allocation. It says no unit is put to a job the man does not believe the good can do.

  • unitsAlike is a field of the stock. It says every unit is believed to serve exactly the ends the good can serve, by his lights (stock.serves). So once a stock holds at least one unit, unitsAlike fixes stock.serves: it is the set of ends each unit is believed to serve.

Three claims quantify over those ends (see The claims). Two are the claims of the two routes: swap dominance (SwapDominant) and serving in order of urgency (ServedInOrder). The third is acting in order of urgency (ActsInOrder), the claim of the history reading. So, in a stock with at least one unit, unitsAlike fixes the ends these claims speak of. (With no units it says nothing, so it fixes nothing.) That is the work it does, though no proof uses it (see below).

Neither condition is a binder in any statement: a binder is one thing a statement takes as an argument (see The manifest). Each is a field inside such an argument: unitsAlike inside the stock, servesOnlyWhatItCan inside the plan or the allocation. So neither condition appears in the signature. Lean builds no stock without a proof of its unitsAlike, and no plan or allocation without a proof of its servesOnlyWhatItCan. So whoever supplies one has already discharged its condition, that is, proved it. Both conditions are still assumptions the theorems rest on. So #manifest reads one level in and reports them, and they are not hidden.

The two are not alike, and the manifest does not pretend otherwise:

  • Take a plan that puts a horse to a job the man does not believe a horse can do. That is not a situation that might obtain. It is an incoherent plan. So servesOnlyWhatItCan assumes nothing about the world. The same field on an allocation is said of what he did. It assumes nothing either.

  • A lame horse is a situation that might obtain. Say the man does not believe it can do a job he believes his other horses can do. Then his units are not believed to serve the same ends, and unitsAlike fails. So unitsAlike does assume something about the world.

Whether a carried condition assumes something about the world cannot be read off its statement in Lean. It is a judgement about the world, so #manifest cannot make it (see The manifest). It is made by hand, and the two bullets above are that judgement.

The library has a rule for a condition that can fail. It becomes a named hypothesis wherever the linter allows. The linter allows a hypothesis only where some proof uses it. So such a condition stays a field only where no proof uses it. The rule does not say which of those stay.

A third condition used to sit here, and now sits nowhere: one unit to one end. That can fail of a real stable. Two horses can pull one wagon, or a horse can stand idle. No theorem's proof uses it, so it is not a hypothesis. Nor is it a field. Dropping it loses nothing: every plan that met it is still a plan, and the law still holds of it. See The other findings.

unitsAlike can fail too, yet it stays a field. No theorem's proof uses it, so as a hypothesis it would fail the unused-argument linter. Marking it with _ would record that it does no work. But it does work: it fixes the ends the three claims above speak of. So it stays a field, and #manifest reports it.

Interchangeability of units is not hidden down there. The plan is indexed by which exact units the man holds. That it depends only on how many of them there are is a separate named condition (AllocationPlan.Homogeneous). It is given in full under The conditions, along with the other conditions.

The history reading is under The ladder as a history. It puts an actual allocation (Allocation) where the plan was. It reads the supply growing (Stock.Grows) as something that happened. Yet no theorem carries Stock.Grows:

  • The ladder judged on the earlier scale (Temporal.ladder_judged_earlier) does not need the growth. Added to that theorem as a hypothesis, the growth fails the unused-argument linter. The theorem's earlier scale is the ranking he held at the moment the theorem calls earlier (earlierTime). Nothing in the theorem orders its two times.

  • The ladder judged on the later scale is written out as a statement (Temporal.LadderJudgedLaterFromOrder). That statement takes the growth as a hypothesis. It is the only one that does. A counter-model shows it false (Model.later_judged_ladder_fails).

Apodictic.Allocation {praxis : ActionFrame} {agent : praxis.Agent}
  {time : praxis.Time} (stock : Stock praxis agent time) : Type
Apodictic.Allocation
  {praxis : ActionFrame}
  {agent : praxis.Agent}
  {time : praxis.Time}
  (stock : Stock praxis agent time) : Type

An actual allocation — what the agent does with the stock he holds at its time. It records the ends he serves with it, and nothing else.

This is the object of the TEMPORAL reading of the law, the ladder read as a history (Apodictic.Temporal). AllocationPlan assigns served ends to every sub-stock at once. That is the standing disposition the counterfactual readings need: Rothbard's route and Mises's, which ask what he would do with fewer units than he holds. This structure instead records one allocation of one stock at one time. It is indexed by nothing: not by sub-stock, not by size. What the agent would have done with fewer units is not in it. It cannot be asked of it. Mises's history — "if the supply available increases from n–1 units to n units" — is then two of these at two times. It is not one plan read at two sizes.

Audit note on shape: servesOnlyWhatItCan is definitional, as for the plan. Putting a unit to an end the good is not believed able to serve is not an allocation of that good.

Like the plan, an allocation is a thing over and above Action. An Action has one chosen end. A stock of several units serving several ends is several actions, or one action whose end is a bundle. The library does not say which, and no theorem asks.

The supply grows by one — Mises's "the supply available increases from n–1 units to n units", read as a history. The stock at the later time holds every unit of the stock at the earlier time, and one more.

It says nothing about the order of the two times. Time carries no order, and this definition does not ask for one. The words "earlier" and "later" are only the names of the two stocks. Nothing says the first stock's time comes before the second's. Leaving the order out lets a theorem show whether it needs one. The earlier-judged ladder (Apodictic.Temporal.ladder_judged_earlier) needs neither this definition nor any order on the two times.

The words of exchange are defined under Exchange, where they are used: a trade, an exchange, and what a holding counts for. The dates time preference needs are defined under Time preference: a bare "before", the time an end is attained, and which ends are the same satisfaction. The frame above has none of them.
