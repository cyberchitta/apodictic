1.16. The vocabulary🔗

Reference. These are the definitions the statements above are written in. Nothing earlier depends on having read them.

The basic vocabulary is deliberately bare. Preference is just a relation. It is not assumed transitive. It is not assumed to rank every pair. Time is not assumed ordered. Properties get added when a theorem forces them. So far one has been added as a claim: asymmetry (AsymmetricPreference). Others enter as conditions of particular theorems. Asymmetry is spent in three places:

  • The theorem relating the two routes spends it (Contrast.rothbard_entails_servedInOrder), under Mises's route.

  • The rival-plan theorem spends it (no_rival_swap_dominant), under The theorems.

  • Four theorems under Interest spend it: the three loan theorems, and the check on the unrestricted rule (PureInterest.buysMore_of_unrestricted).

The vocabulary everything else is built from: bare types and bare relations. Nothing here has any property. Preference is not assumed transitive. It is not assumed to rank every pair. Time is not assumed ordered. A property gets added only when some theorem forces it. Every such forcing is a finding.

Constructor

Apodictic.ActionFrame.mk

Fields

Agent : Type

Acting persons.

End : Type

Ends: states of affairs an agent may value.

Means : Type

Means: scarce resources an agent may employ.

Time : Type

When action happens. It is explicit from the start. No order is assumed on it here.

Believes : self.Agent → self.Time → self.Means → self.End → Prop

Believes agent time means want: at that time, the agent believes that using those means helps bring about that want. Nothing links a means to an end here except what the agent believes.

Prefers : self.Agent → self.Time → Set self.End → Set self.End → Prop

Prefers agent time X Y: at that time, the agent values the bundle of ends X above the bundle Y. This is the ranking behind the agent's choices. It is read as strict. But that reading is not built in: NO properties are imposed on this relation, strict or otherwise. A theorem that needs one says so.

The ranking is kept apart from what the agent actually does. Three claims tie the two. Two run from an act to the ranking. DemonstratedPreference is stated of a trade. DemonstratedTimePreference is stated of an act across dates. One runs the other way, from the ranking to what he does with a stock. ActsInOrder is stated of an actual allocation. Each is asserted of the one trade, act or allocation a theorem is handed, never of every act.

The relation ranges over SETS of ends rather than single ends. The tradition draws no line between an end and a composite of ends. The word "atomic" only ever means "not divided further by this action". That is the same relativity as the size of a unit of supply (MES p. 28). So there is ONE ranking, over bundles at whatever grain the problem has. An end in the ordinary sense is a bundle with one member (PrefersEnd). Independence of uses (IndependentUses) is bundle preference breaking down into preference between ends. Ranging over bundles is what lets it be a named hypothesis, instead of something the vocabulary quietly enforces.

Shape claim (audit): a bundle is a Set, so it carries no multiplicity and no order.

The law is about a stock of units and what the agent would do with more or fewer of them.

🔗structure
Apodictic.Stock (praxis : ActionFrame) (agent : praxis.Agent)
  (time : praxis.Time) : Type
Apodictic.Stock (praxis : ActionFrame)
  (agent : praxis.Agent)
  (time : praxis.Time) : Type

A stock of some good, held by one agent at one time. It is finitely many units the agent believes will do the same jobs.

"The same jobs" is the whole of what homogeneity means here. Each unit is believed to serve exactly the ends in serves. That is a statement about BELIEF, not about preference. Nowhere is it said that the agent is indifferent between units. So preference can stay strict. And Rothbard's denial that indifference is ever demonstrated in action is not contradicted. Is doing the same jobs enough for the law? Or is indifference between units needed after all? That is then something to check. It is not assumed away.

What counts as a unit is left open. units lists whatever enters the action as one thing. Rothbard holds that the law works "regardless of the size of the unit considered. The size of the unit will be the one that enters into concrete human action" (MES p. 28). Pairs of horses make a different stock, with a "new and shorter scale of ends". A good that "cannot be divided into homogeneous units for purposes of action" is a stock of exactly one unit.

🔗structure
Apodictic.AllocationPlan {praxis : ActionFrame} {agent : praxis.Agent}
  {time : praxis.Time} (stock : Stock praxis agent time) : Type
Apodictic.AllocationPlan
  {praxis : ActionFrame}
  {agent : praxis.Agent}
  {time : praxis.Time}
  (stock : Stock praxis agent time) : Type

The agent's plan for the stock. Take each subStock, each set of units he might have. The plan gives the ends he WOULD serve with exactly those units, at the stock's single time.

The plan is something new, over and above Action, and it has to be. A single act of allocating cannot tell the served ends apart from one another. They all sit inside the one package chosen. So what the law of marginal utility rests on is not action at all. The plan is a separate thing, and no act of the agent's exhibits it.

The plan is indexed by WHICH units, not by how many. To say it depends only on the number of them is to say the units are interchangeable. That is not built in here. It is the named condition Homogeneous, assumed only where a theorem needs it.

Field-shape claim (audit): servesOnlyWhatItCan is the one condition left in the plan's fields. It is definitional. Take a plan that puts a unit to an end the good is not believed able to serve. That is not a coherent plan. It is not a situation that might obtain.

One unit to one end is NOT here, and is nowhere: no theorem needs it. Rothbard assumes it, and says he is assuming it. He writes "each unit of means is capable of serving one of the ends". He introduces it with "We assume for simplicity" (MES pp. 25–26). The ordering the law asserts turns out not to want it. Where an extra unit adds no new end, the law is silent. That costs nothing.

Apodictic.AllocationPlan.mk

Fields

wouldServe : Finset praxis.Means → Finset praxis.End

The ends the agent would serve with exactly the units in subStock, and no others.

servesOnlyWhatItCan : ∀ (subStock : Finset praxis.Means), ∀ want ∈ self.wouldServe subStock, want ∈ stock.serves

A unit is only ever put to an end the good is believed able to serve.

Two conditions sit a level down. They are fields of the structures the theorems take as arguments: the stock, the plan, and on the history reading an allocation.

  • servesOnlyWhatItCan is a field of the plan and of an allocation. It says no unit is put to a job the man does not believe the good can do.

  • unitsAlike is a field of the stock. It says every unit is believed to serve exactly the ends in stock.serves. So once a stock holds at least one unit, unitsAlike fixes stock.serves: it is the set of ends each unit is believed to serve. Three claims quantify over those ends (SwapDominant, ServedInOrder, ActsInOrder).

Neither condition is a binder in any statement. Both are on the manifest regardless. #manifest reads one level in and reports them. It does so because whoever supplies the argument has already discharged them.

The two are not alike, and the manifest does not pretend otherwise:

  • Take a plan that puts a horse to a job the man does not believe a horse can do. That is not a situation that might obtain. It is an incoherent plan. So servesOnlyWhatItCan assumes nothing about the world. The same field on an allocation is said of what he did. It assumes nothing either.

  • A lame horse is a situation that might obtain. So unitsAlike does assume something about the world.

Which of the two a carried condition is cannot be read off the term. It is ruled by hand, and this is the ruling.

A third condition used to sit here, and now sits nowhere: one unit to one end. That can fail of a real stable. Two horses can pull one wagon, or a horse can stand idle. So it could not stay a field. Taking it out showed that no theorem wants it. So it was not made a hypothesis either. See The other findings.

Interchangeability of units is not hidden down there. The plan is indexed by which exact units the man holds. That it depends only on how many of them there are is a separate named condition (AllocationPlan.Homogeneous). It is given in full under The conditions, along with the other conditions.

The history reading is under The ladder as a history. It puts an actual allocation (Allocation) where the plan was. It reads the supply growing (Stock.Grows) as something that happened. No theorem carries Stock.Grows. Added as a hypothesis of the earlier-judged ladder (Temporal.ladder_judged_earlier), it fails the unused-argument linter. As a hypothesis, it appears only in the statement the counter-model (Model.later_judged_ladder_fails) refutes (Temporal.LadderJudgedLaterFromOrder).

🔗structure
Apodictic.Allocation {praxis : ActionFrame} {agent : praxis.Agent}
  {time : praxis.Time} (stock : Stock praxis agent time) : Type
Apodictic.Allocation
  {praxis : ActionFrame}
  {agent : praxis.Agent}
  {time : praxis.Time}
  (stock : Stock praxis agent time) : Type

An actual allocation — what the agent does with the stock he holds at its time. It records the ends he serves with it, and nothing else.

This is the object of the TEMPORAL reading of the law (Apodictic.Temporal). AllocationPlan assigns served ends to every sub-stock at once. That is the standing disposition the counterfactual reading needs. This structure instead records one allocation of one stock at one time. It is indexed by nothing: not by sub-stock, not by size. What the agent would have done with fewer units is not in it. It cannot be asked of it. Mises's history — "if the supply available increases from n–1 units to n units" — is then two of these at two times. It is not one plan read at two sizes.

Field-shape claim (audit): servesOnlyWhatItCan is definitional, as for the plan. Putting a unit to an end the good is not believed able to serve is not an allocation of that good.

Like the plan, an allocation is a thing over and above Action. An Action has one chosen end. A stock of several units serving several ends is several actions, or one action whose end is a bundle. The library does not say which, and no theorem asks.

The supply grows by one — Mises's "the supply available increases from n–1 units to n units", read as a history. The stock at the later time holds every unit of the stock at the earlier time, and one more.

It says nothing about the order of the two times. Time carries no order, and this definition does not ask for one. The words "earlier" and "later" are the names of the two arguments. They are not a relation between their indices. Leaving the order out lets a theorem show whether it needs one. The earlier-judged ladder (Apodictic.Temporal.ladder_judged_earlier) needs neither this definition nor any order on the two times.

The words of exchange are defined under Exchange, where they are used: a trade, an exchange, and what a holding counts for. The dates time preference needs are defined under Time preference: a bare "before", the time an end is attained, and which ends are the same satisfaction. The frame above has none of them.
